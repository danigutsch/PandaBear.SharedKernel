# SharedKernel.Testing.SourceGenerator

Incremental source generator for `PandaBear.Testing.CallProxy`. It has no standalone package: it ships inside
`PandaBear.SharedKernel.Testing` as `analyzers/dotnet/cs/SharedKernel.Testing.SourceGenerator.dll`, so a test project that references
that package directly receives the generator. A package that depends on `PandaBear.SharedKernel.Testing` does not pass its analyzers on,
so reference it directly from every test project that wraps a service.

## Behavior

The generator finds the interfaces a test wraps or hooks:

- `CallProxy.Create<T>(...)`, with `T` written or inferred from the first argument;
- `services.WrapWithCallProxy<T>(...)`;
- a hook added through `CallHooks<T>`, such as `hooks.Find.Before(...)` in a helper that takes `CallHooks<IStore>`.

A `T` that is a type parameter is skipped: wrap through a generic helper of your own only for interfaces that are also named in one of
the forms above, or `CallProxy.Create` throws an `InvalidOperationException` that says so.

For each interface it writes one file, `CallProxy.<Namespace_Type>.g.cs` (every character that is not a letter or digit becomes `_`;
a name already taken gets `_2`), with one `internal static class CallProxyFor_<Namespace_Type>` in the `PandaBear.Testing` namespace, so
the members are in scope wherever `CallProxy` is. It holds:

- C# 14 extension members of `CallHooks<T>`: one property per method, named after the method, of type `MethodHooks<TCall>` for a method
  without a result (`void`, `Task`, `ValueTask`) or `MethodHooks<TCall, TResult>` for a method with one (`TResult`, `Task<TResult>`,
  `ValueTask<TResult>`); only the latter has `Returns`;
- one call class per method, `<Method>Call`, with a get-only property per argument (the parameter name with its first letter upper-cased)
  and, for a method with a result, `Result`;
- a hooks holder derived from `GeneratedCallHooks<T>` and a private proxy class that implements every method explicitly: it runs the
  before hooks, calls the real service (or takes the `Returns` value), runs the after hooks, and returns;
- a module initializer that registers the holder, so `CallProxy.Create<T>(inner)` works without hooks too.

Methods of inherited interfaces and methods with default implementations are proxied as well. Members are ordered as declared, the
interface's own first, then its inherited interfaces.

Naming rules, so a member name never depends on anything but the interface:

- Overloads: every overload of a name gets its parameter type names appended, such as `Save_Int32` or `Find_Guid_CancellationToken`
  (arrays end in `Array`, generic types list their type arguments: `List<Guid>` is `ListGuid`); a parameterless overload is
  `Save_NoParameters`.
- A method named like a member of `CallHooks<T>` (`Equals`, `Generated`, `GetHashCode`, `GetType`, `ReferenceEquals`, `ToString`) gets
  `Method` appended, such as `ToStringMethod`.
- An argument property named like `Result`, its call class, or an inherited member gets `Argument` appended, such as `ResultArgument`.
- A name that is still taken gets `_2`, `_3` and so on, in declaration order.

## Example

```csharp
public interface ICustomerStore
{
    Task<Customer?> Find(Guid id, CancellationToken ct);
    Task<bool> EmailExists(string email, CancellationToken ct);
}

var store = CallProxy.Create<ICustomerStore>(real, hooks =>
{
    hooks.Find.After(call => DeleteRow(call.Id, call.Result));
    hooks.EmailExists.Returns(false);
});
```

The generated `CallProxy.Demo_ICustomerStore.g.cs` starts with:

```csharp
// <auto-generated />
#nullable enable

namespace PandaBear.Testing
{
    internal static class CallProxyFor_Demo_ICustomerStore
    {
        extension(global::PandaBear.Testing.CallHooks<global::Demo.ICustomerStore> hooks)
        {
            public global::PandaBear.Testing.MethodHooks<FindCall, global::Demo.Customer?> Find => hooks.Generated<HookSet>().Hooks0;
            public global::PandaBear.Testing.MethodHooks<EmailExistsCall, bool> EmailExists => hooks.Generated<HookSet>().Hooks1;
        }
        // call classes, the hooks holder, the proxy class, and the module initializer follow
    }
}
```

## Diagnostics

The generator owns the `SKPRX` prefix. Every diagnostic is an error and generates nothing for that interface.

### SKPRX001

The wrapped type is not an interface, such as `CallProxy.Create<Clock>(clock)` for a class. Wrap the interface the class implements.

### SKPRX002

The interface cannot be implemented by a top-level class of the test assembly: it is `private` or `protected` inside a type, or internal
to another assembly without `InternalsVisibleTo`. Public and internal interfaces are fine.

### SKPRX003

A member of the interface has no typed hooks, so the interface cannot be proxied: a property, an indexer, an event, a generic method, a
method with a `ref`, `out` or `in` parameter, a method that returns by reference, a method with a variable argument list, or a method with
a ref struct (such as `Span<T>`) or pointer parameter or result. The message names the member. Wrap a narrower interface, or write a
hand-made fake for that service.

### SKPRX004

The project compiles a C# version before 14. The typed hooks are C# 14 extension members, the default for .NET 10; remove an older
`LangVersion`.

C# namespace: `PandaBear.Testing.SourceGenerator`. Assembly and project identity: `SharedKernel.Testing.SourceGenerator`.
