# SharedKernel.EventSourcing.Npgsql

[![Repository-wide build status](https://github.com/danigutsch/PandaBear.SharedKernel/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/danigutsch/PandaBear.SharedKernel/actions/workflows/ci.yml)

Packages remain preview (prerelease); stable packages, tags, and releases require separate authorization.

Raw Npgsql adapter for the storage-neutral `SharedKernel.EventSourcing` abstractions.

This package owns reusable event-stream and projection-checkpoint persistence. Bounded contexts still
own composition, schema naming, migrations/initialization policy, and context-specific read models.

The schema in `PostgreSqlEventSourcingOptions.Schema` must pass `PostgreSqlIdentifier.IsUnquoted` from
`PandaBear.SharedKernel.PostgreSql`: ASCII letters, digits, and `_`, not starting with a digit, at most 63 bytes. A
longer name, which PostgreSQL would silently truncate, is refused with `ArgumentException` like any other invalid name.

### Controlled metadata time

Set `PostgreSqlEventSourcingOptions.TimeProvider` when constructing either store with a controlled clock.
Existing constructors default to `TimeProvider.System`. Capture the application-registered provider in this options
object when composing the stores; the package remains independent of a DI host. Each nonempty append reads the
clock once after acquiring the append lock, before stream creation, and reuses that instant for stream creation,
every event, and the stream revision update. Later appends preserve stream creation time. Checkpoint saves use
the configured clock. PostgreSQL timestamps retain the database's microsecond precision; UUIDv7 IDs remain
independently generated by the event store.

### Event causation

Use the `IEventStore.Append` overload with `causationEventId` when the caller knows the exact event that caused
an append. The provider commits the same UUID on every event in the batch. Append results, stream loads and
global position loads all return it in `EventEnvelope.CausationEventId`. Existing appends and historical rows
have a null value. The application owns the correlation and may identify events from another store.

Run `PostgreSqlEventSourcingSchema.Initialize` as the schema owner before starting the upgraded provider.
Initialization adds a nullable `causation_event_id` column to existing event tables and can be repeated.
Existing direct SQL readers and inserts using explicit columns continue to work after the schema upgrade.
A provider that implements only the original `IEventStore.Append` overload reports `NotSupportedException`
if asked to record causation.
